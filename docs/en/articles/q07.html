🔨 Layer 2 · The Beginner Coder's View

How is a webpage actually made?

Congrats — you're about to become a creator

🤔 The ordinary user's view: why does this matter?

You look at webpages every day. But have you ever stopped to ask: how are these pages actually created?

This question matters because it marks a shift: from "user" to "creator."

The awakening of Layer 2:

Webpages don't just "grow" on the internet —
someone writes them, line by line!

And if someone else can write one, so can I.

Once you get that, the whole internet looks different. What you see stops being "stuff that already exists" — it becomes "stuff I could build too."

🧩 Breaking it down: big problem into small ones

To build a webpage, you really only need to understand three things:

  1. Structure: what's on the page? (headings, images, buttons...)
  2. Style: what does it look like? (color, size, position...)
  3. Behavior: what does it do? (respond to clicks, change data...)

And, conveniently, these three things map onto three technologies.

Let's look at them one by one.

📄 HTML: the content skeleton

HTML is like the outline of an article — it says "this is a heading, that's a paragraph, there's an image over here."

The simplest HTML looks like this:

<!-- This is a comment -->
<html>
<head>
<title>My first webpage</title>
</head>
<body>
<h1>Hello World!</h1>
<p>This is a paragraph.</p>
</body>
</html>

See? HTML uses "tags" to define content. Just like how you use "heading" and "paragraph" to organize a piece of writing.

🎨 CSS: style and good looks

Content alone isn't enough — we want it to look nice. That's CSS's job.

Say we have a heading. CSS gets to decide:

h1 {
color: #10B981; /* green */
font-size: 32px; /* font size */
text-align: center; /* centered */
}

CSS's power is that it's declarative. You just say "I want it like this" — and the browser handles the rest.

⚡ JavaScript: bring the page to life

Last piece — interaction. Users click, we react. Users type, we respond. That's JavaScript's job.
// When the button is clicked...
button.addEventListener('click', function() {
alert('Hello!'); // pop up a message
});

Alright — now let's unite the three musketeers and build a real webpage.

✋ Live demo: your first webpage!

Let's put HTML, CSS, and JavaScript together:

<!DOCTYPE html>
<html>
<head>
<style>
body { background: #F9FAFB; text-align: center; padding: 50px; }
button { background: #10B981; color: white; padding: 15px 30px; border: none; border-radius: 8px; font-size: 18px; cursor: pointer; }
</style>
</head>
<body>
<h1>🎉 My first webpage!</h1>
<p>Try clicking the button below~</p>
<button id="magic-btn">✨ Click me ✨</button>
<p id="result"></p>
<script>
let count = 0;
document.getElementById('magic-btn').addEventListener('click', function() {
count++;
document.getElementById('result').innerText = `You've clicked ${count} times!`;
});
</script>
</body>
</html>

Congratulations — what you just saw is the entire source of a complete modern webpage.

→

This happens every time you open a page — and even every time you scroll. The browser is a tireless painter.

⚖️ The trade-off layer: why design it this way?

By now you might be asking: why split it into three languages? Why not just merge them into one?

Separation of concerns!

  • HTML: what is this thing?
  • CSS: what does this thing look like?
  • JS: what does this thing do?

Once they're separated, changing one doesn't break the other two.

That's the wisdom of software design: keep different concerns in different places.

👑 The Grandmaster's View: how does this shape reality?

From code to power

Once you get that "webpages are written," you start to realize something:

Everything you see online is something someone decided to show you.
And behind those decisions — there are values, business, politics, biases.

Think about these:

  • Why is this button so big? Is it to make you click it more easily?
  • Why is this option buried so deep? Do they not want you to find it?
  • Why does this color make me feel urgent? Is that on purpose?
  • Why can't I put this app down? What psychological tricks are in play?

That's the shift from "just using" to "seeing through." What you see stops being "the way things are" — it becomes "someone designed this."

✨ Back to the question

So — how is a webpage actually made?

The answer:
Define structure with HTML, style with CSS, behavior with JavaScript — and let the browser turn all three into pixels on your screen.

But that's not the whole truth.

The deeper truth is:

You can make webpages too.
You can be one of the creators of this world.

Congrats — starting today, the way you see the internet is different.
