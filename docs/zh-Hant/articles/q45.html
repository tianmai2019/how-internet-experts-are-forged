🤖 第6層認知 · AI 時代視角

為什麼AI沒有讓互聯網變簡單，而只是把複雜性藏得更深？

AI 不是新的抽象——它是新的黑盒

🤔 小白視角：這個問題為什麼重要？

過去兩年，很多人都有一種幻覺：

"AI 來了，以後不用學 SQL 了。"
"AI 來了，以後不用寫代碼了。"
"AI 來了，一切都會變簡單。"

可你真的開始用 AI 做事之後，會發現完全不是這樣——

  • 你要學 Prompt 工程：怎麼問才能得到想要的答案。
  • 你要理解 RAG：為什麼你的私有文檔還得先切成小塊、算向量、存到數據庫裡。
  • 你要評估 Agent 工作流：一個用戶問句怎麼就調用了 40 次工具、6 個 API、3 個模型？
  • 你要處理 幻覺、評估、監控、成本……

互聯網沒有變簡單。相反，複雜性被推到了更深的地方——用戶看不見，但工程師要面對更多。 這個問題重要，是因為如果你以為 AI = 簡單，你就會低估自己該學什麼、該防什麼。

🧩 拆解：把大問題拆成小問題

  1. 什麼是"抽象"？為什麼每一層抽象都帶來簡化又帶來復雜？
  2. 用戶看到的"簡單"，背後隱藏了什麼？
  3. AI 系統的"黑盒"，比過去的黑盒有什麼不同？
  4. 為什麼這種"隱藏"其實是問題，也是機會？

🎯 一層一層看

用戶層：只看結果

你打開 ChatGPT，輸入一句話，得到一段回答。整個體驗只有一個輸入框和一段文本—— 比 Google 還簡單。你可能覺得這就是"未來"該有的樣子。

但你沒看到的是：這一次簡單的交互，可能在後臺調用了幾十層系統。 你看到的"簡單"，是精心設計的抽象層——就像水龍頭背後是整個自來水廠。

實現層：開始理解構造

讓我們展開一次"簡單"的 AI 問答，看看真實發生了什麼：

你輸入： "幫我總結一下這份合同的關鍵條款" 系統真實鏈路（簡化版）： 1. 前端攔截 → 分類："文檔任務" 2. 檢查用戶權限、訂閱、剩餘額度 3. 加載 system prompt（可能幾千字，你看不到） 4. 檢查安全策略（拒答規則、內容審核） 5. RAG 檢索：把你上傳的合同切片 → 向量化 → 相似度檢索 → 拿回 top-k 段落 6. 組裝最終 prompt：system + 檢索片段 + 你的問題 7. 路由到合適的模型（成本 / 延遲 / 能力） 8. 模型推理（幾百層 Transformer，幾十億參數運算） 9. 輸出審核：過濾敏感內容 10. 若模型觸發"工具調用" → 調外部 API → 結果回填 → 再推理 11. 若是 Agent → 循環 5-10，規劃、執行、反思，可能來回 10+ 次 12. 記錄 tokens、成本、延遲到監控系統 13. 返回給你：一段流暢的文本

你看到的一句話，背後是十幾層子系統在協作。 Prompt engineering、Embedding、Vector DB、Retrieval、Reranking、Tool use、Agent orchestration、 Guardrails、Evals、Observability——這些名詞每一個都是一整個新興學科。

系統層：看到完整鏈路

把它放進"互聯網的複雜性演化史"裡看，你會看到一個清晰的規律：

80s：命令行 → 文件、進程
↓ 抽象一層
90s：圖形界面 → 窗口、點擊
↓ 抽象一層
00s：網頁 → 鏈接、搜索
↓ 抽象一層
10s：App → 手指滑動、通知
↓ 抽象一層
20s：AI → 對話、意圖

每一次抽象，都是把複雜性向下壓一層——用戶端看起來更簡單， 但下面的系統越壘越高。 今天的一次"你好，幫我寫個郵件"背後，是過去 60 年所有基礎設施的總和，再加上一層全新的 AI 層。

🖥️ 傳統抽象（如操作系統、Web 框架）

隱藏細節，但可打開：
看得到源碼、可以打斷點、可以讀文檔。
黑盒是"我暫時不看"，不是"我看不到"。

🤖 AI 抽象

隱藏細節，而且真的打不開：
權重不可讀、推理路徑不可解釋、失敗模式無規律。
黑盒是"沒人能真正看清裡面發生了什麼"。

權衡層：為什麼這樣設計？

你可能會問：既然更復雜了，為什麼大家都在推 AI？ 因為它換來了一個前所未有的價值——意圖級交互。

以前，你要告訴計算機"怎麼做"：點這裡、拖那裡、寫這段 SQL。 現在，你只要說"我想要什麼"，AI 層負責翻譯成執行動作。 這是從過程式交互到目標式交互的一次躍遷。

這帶來了新的權衡：
  • 用戶體驗↑，工程複雜度↑↑
  • 入門門檻↓，深入門檻↑
  • 產品能做的事↑↑，能保證的事↓
簡單和複雜在系統中守恆——它不會消失，只會轉移。
常見誤區："AI 讓人不用寫代碼了。"
更準確的說法是："AI 讓寫代碼的人可以更快，讓不寫代碼的人可以做更多事—— 但要負責一個真正生產級的 AI 系統，需要的技能反而更多，而不是更少。"
能"用" ≠ 能"負責"，這是關鍵分野。

✋ 動手試試

拆解一次"AI 對話"

找一個開源的 RAG 項目（LangChain、LlamaIndex 的 quickstart 都可以）， 自己搭一個"和你的 PDF 對話"的最小 demo。

你會親手體驗到：

  1. 切片（chunking）該切多長？
  2. 用哪個 embedding 模型？
  3. 向量數據庫選哪個？
  4. 檢索出的 chunk 怎麼排序？
  5. Prompt 裡怎麼組合上下文？
  6. 模型答歪了怎麼調？

這個練習會讓你永久意識到：一次"簡單"的對話背後，是一整個技術棧—— 而這個棧的每一層都能出錯，都需要你懂它。

👑 大帝視角：這如何塑造現實？

複雜性不會消失，它只會換個地方躲起來

計算機科學裡有一條古老的定律，叫 Tesler's Law of Conservation of Complexity（複雜性守恆律）： 任何系統的複雜度是固定的，你只能把它從一處推到另一處——通常從用戶推給工程師，從前端推給後端， 從產品推給基礎設施。

AI 是這條定律最戲劇化的一次演出：

  • 它把用戶面對的複雜度壓到了幾乎為零——只剩一個對話框。
  • 它把工程師面對的複雜度堆到了歷史新高——多模型、多工具、多 agent、多評估維度。
  • 它把社會面對的複雜度也放大了——版權、偏見、責任歸屬、安全、就業結構。

第 6 層認知的意義在於：看穿"簡單"的表象，理解複雜的走向。 當你意識到 AI 不是把互聯網變簡單，而是把複雜性藏得更深，你就會用不同的姿勢去學、去用、去做產品。

真正的大帝，不追求"沒有複雜性"——因為那是幻覺。 真正的大帝追求的是：知道複雜性躲在哪，能在需要時把它翻出來看一眼。

✨ 回到問題

為什麼 AI 沒有讓互聯網變簡單，而只是把複雜性藏得更深？

因為"簡單"從來不是一個絕對狀態，而是一個抽象層的產物。 AI 是互聯網歷史上最激進的一次抽象——它把複雜度整體下沉到"模型 + 工程棧"這一層， 讓用戶以為世界變簡單了，實際上是需要理解世界的人越來越少了，但需要為世界負責的人要懂得更多了。

如果你只想"用"，AI 時代很簡單；
如果你想"做"，AI 時代前所未有地複雜；
如果你想"理解"——歡迎來到第 6 層認知。

合上這篇文章前，問自己一個問題：
下一次當有人告訴你"這東西很簡單"時，你會不會本能地追問一句——
"那複雜性去哪了？"

如果你會，你已經不是那個只看到"對話框"的人了。
