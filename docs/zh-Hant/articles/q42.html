為什麼生成式AI和傳統軟件系統在本質上不一樣？

從"規則→輸出"，到"分佈→採樣"

🤔 小白視角：這個問題為什麼重要？

過去 60 年，我們對"軟件"的直覺是這樣的： 你寫代碼，代碼規定"如果 A，就做 B"，然後機器按你寫的做。 Excel 一定按公式算，登錄接口一定按邏輯判斷密碼——軟件是可預期的機器。

但用過 ChatGPT 的人都有這種感覺："這東西怎麼用起來完全不一樣？" 同一個問題問兩次，答案不一樣；有時候特別聰明，有時候特別蠢。 它更像一個捉摸不定的合作者，而不是一臺機器。

為什麼會這樣？
因為它壓根不是"傳統意義上的軟件"。
傳統軟件的核心是規則，生成式 AI 的核心是分佈——這是兩種世界觀。

🧩 拆解：把大問題拆成小問題

  1. 傳統軟件是怎麼"決定"輸出的？
  2. 生成式 AI 是怎麼"決定"輸出的？
  3. 為什麼兩者會長得越來越像，本質卻完全相反？
  4. 這對我們做工程有什麼根本影響？

🎯 一層一層看

用戶層：只看結果

作為用戶，你看不出計算器和 ChatGPT 有什麼"本質"區別——都是輸入一段文字，出來一段結果。 但你會隱約感覺到：計算器是"工具"，ChatGPT 更像"對象"。 你不會跟計算器"討價還價"，但你會跟 AI 反覆"聊"，希望它答得更好。

實現層：開始理解構造

在實現層，兩者的差別一覽無餘。傳統軟件是顯式規則，代碼寫死了邏輯：

// 傳統軟件：SQL 查詢 SELECT price FROM products WHERE id = 42; // 結果是"確定的"：只要數據沒變，答案永遠一樣。 // 42 號產品的價格是 128.00 元。就是這樣。就是這樣。

生成式 AI 完全不同。它沒有 if/else，沒有查詢表——它是一個裝著幾千億參數的大矩陣， 這些參數（weights，權重）在訓練時被"喂海量數據"調整過：

// 生成式 AI：LLM 補全 prompt = "42號產品的價格是" → 前向計算通過神經網絡（幾百層 Transformer） → 每一層做的都是矩陣乘法 + 非線性變換 → 最終輸出一個"下一個 token 的概率分佈" → 採樣得到："128 元" // 結果是"分佈的"：同樣輸入兩次，可能得到不同答案。 // 因為它是從概率分佈裡採樣，不是查表。

這裡的 权重 你可以粗暴理解為：一堆學出來的數字， 它們編碼了模型"見過的所有文字之間的統計關係"。模型不存文字，模型存的是"模式"。

系統層：看到完整鏈路

當你把這兩種系統放到"整個鏈路"裡看，它們的差異是驚人的：

🏛️ 傳統軟件

範式：規則 → 輸出
邏輯寫在哪：代碼裡，人類寫的
可解釋性：可以逐行讀
可預測性：同輸入 → 同輸出
失敗方式：拋異常、報錯
調試方式：加日誌、打斷點

🌀 生成式 AI

範式：分佈 → 採樣
邏輯寫在哪：權重裡，訓練時"長出來的"
可解釋性：只能觀察，無法逐行讀
可預測性：同輸入 → 分佈相同、樣本可能不同
失敗方式：不報錯，只是輸出錯的但看起來對的
調試方式：改 prompt、加 RAG、微調、評估

注意最扎心的那一行：失敗方式。 傳統軟件失敗時會大聲報錯（"NullPointerException！"），你至少知道出錯了。 生成式 AI 失敗時安靜地繼續說話——你可能讀了半天都沒意識到它錯了。

常見誤區："AI 只是複雜一點的軟件。"
不對。它是另一類軟件。 你不能用"給傳統軟件調 bug"的姿勢去用 AI——那會讓你既失望又困惑。

權衡層：為什麼這樣設計？

有人會問：既然分佈式採樣這麼不確定，為什麼不乾脆做成確定式規則？ 答案是——做不到。

寫一段"總結這篇文章"的規則？你沒法把"總結"變成 if/else。寫一段"識別貓的圖片"的規則？ 過去 30 年計算機視覺嘗試了，效果遠不如深度學習。 只要問題涉及"人類語言、感知、創意"，規則式思路就會撞牆—— 因為這些問題的複雜度，超過了人類能顯式寫下的規則數量。

生成式 AI 的關鍵突破，是"跳過定義規則"這一步——直接從數據中湧現（emerge）出能力。 翻譯、推理、寫代碼這些能力，沒人顯式教它，只是模型"變大後自動會了"。 這是我們從沒在傳統軟件裡見過的現象。

關鍵差異總結：
  • 傳統軟件：人先想清楚規則，再讓機器執行。
  • 生成式 AI：人先給數據，讓機器自己"長出"某種能力。
這意味著工程師的角色也變了：從"規則設計者"變成"數據策展人 + 行為觀察者"。

✋ 動手試試

讓兩個系統"同題作答"

打開一個計算器 App 和一個 AI 助手（ChatGPT / Claude / Gemini 都行）。
在兩邊分別輸入："128 × 47 等於多少？"

觀察三件事：
1️⃣ 計算器：每次都得同一個數，快、穩、無解釋。
2️⃣ AI：可能算對，也可能算錯；換個問法結果會變；它還會"解釋推理過程"。
3️⃣ 讓 AI 多試幾次同樣的問題——它可能給出不同的解釋路徑，甚至不同的錯法。

這就是"規則 → 輸出" vs "分佈 → 採樣"最直觀的對比。

👑 大帝視角：這如何塑造現實？

軟件工程正在離開"精確定義"，進入"概率共舞"

過去，"程序員"這個詞代表的是：精確、邏輯、可預測。 你寫下的每一行代碼，都是一句刻在石頭上的判決。

生成式 AI 打破了這個契約。它引入了一種全新的工程文化：

  • 測試從"斷言相等"變成"評估質量"——你不能再斷言輸出等於某字符串。
  • 迭代從"改代碼"變成"改 prompt + 改數據"——bug 可能在文本里，不在代碼裡。
  • 可靠性從"每次一樣"變成"分佈上夠好"——你接受偶爾翻車，只要頻率可控。

這不是軟件工程的死亡，而是它的第二次成年—— 我們第一次要和一種自己不完全理解的東西共同構建產品。 在第 6 層認知裡，你要接受一件事：控制感的減少，是能力擴展的代價。

✨ 回到問題

為什麼生成式 AI 和傳統軟件在本質上不一樣？

因為它們運行在兩種不同的世界觀裡。 傳統軟件的世界，是由人類顯式規則搭起來的確定性積木； 生成式 AI 的世界，是從數據裡生長出來的概率分佈， 每次採樣都是從這片分佈裡"扔一次骰子"。

當你意識到這一點，你就不會再把它當成"更聰明的搜索引擎"， 也不會再期待它"每次都一樣"。你會開始學一門新的語言—— 如何在不確定性中做工程。
