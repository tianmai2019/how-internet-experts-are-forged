為什麼AI系統的輸出帶有概率性，而不是傳統系統那樣的確定性？

AI 的可靠，不是"每次一樣"，而是"分佈上夠好"

🤔 小白視角：這個問題為什麼重要？

你有沒有過這種體驗：

同一個問題問 ChatGPT 兩遍，答案居然不一樣。
第一次它說"是的"，第二次它說"不完全是"。
你頓時懷疑：這東西到底靠不靠譜？

這個疑問的背後，其實是一個很深的問題：為什麼 AI 不像 ATM 一樣，每次輸入密碼都給你同樣確定的結果？

如果理解不了這一點，你要麼會過度信任它（因為它有時候答得特別好）， 要麼會徹底放棄它（因為它偶爾胡說八道）。真正靠譜的姿勢是理解它的"概率性"—— 它的可靠不在"每次一樣"，而在"分佈上夠好"。

🧩 拆解：把大問題拆成小問題

  1. "確定性" vs "概率性"是什麼意思？
  2. 為什麼模型必須做概率採樣，不能直接輸出？
  3. temperature、top-p、seed 到底在控制什麼？
  4. 這對我們把 AI 用作生產系統有什麼影響？

🎯 一層一層看

用戶層：只看結果

作為用戶，你觀察到的現象是：

  • 問一次 → 一個答案
  • 再問一次 → 另一個答案（可能更好，可能更差）
  • 把問題改一個字 → 答案可能天翻地覆

這不是 bug，也不是網絡問題——這是 AI 的本來面目。 傳統系統輸出的是"答案"；AI 輸出的是"從答案的分佈裡抽一個樣本"。

實現層：開始理解構造

在實現層，讓我們直面那個關鍵動作——採樣（sampling）。

模型每一步做的事，都是從一個概率分佈裡"挑一個 token"。假設它算出下一個 token 的分佈是：

Prompt: "今天天氣很" 下一個 token 的概率分佈： "好" → 0.42 "熱" → 0.18 "冷" → 0.12 "悶" → 0.09 "潮溼" → 0.06 "適合" → 0.05 ... 採樣策略決定"怎麼選"： ┌─ greedy（貪心） → 永遠選最高概率 → "好" ├─ temperature = 0 → 等同 greedy，幾乎確定性 ├─ temperature = 0.7 → 按概率隨機採樣，"好"佔多數但會出現別的 ├─ temperature = 1.5 → 分佈被"拉平"，"悶/潮溼"也可能被選中 └─ top-p = 0.9 → 只在累計概率 90% 的候選裡採樣，避免尾巴上的怪詞

這裡的關鍵概念：

  • temperature（溫度）：控制分佈的"陡峭度"。溫度低 → 越傾向最高概率；溫度高 → 越"發散"。
  • top-p（核採樣）：只在累積概率超過 p 的那部分候選裡採樣，把"低概率的怪詞"排除掉。
  • seed（隨機種子）：偽隨機數生成器的起點。同 seed + 同參數 + 同模型 → 理論上同結果。
常見誤區："把 temperature 設為 0，AI 就變確定了。"
部分對，部分不對。temperature = 0 讓採樣變確定， 但 batch 大小、併發調度、浮點算子實現、硬件、tokenizer 版本 都會引入細微差別， 真實生產裡幾乎不可能做到位對位一致。這也是為什麼 OpenAI 的 seed 參數被官方標註為 "best-effort"。

系統層：看到完整鏈路

把視野拉大到系統層，你會看到"概率性"其實來自多個源頭：

1. 模型本身：分佈式輸出
↓
2. 採樣策略：temperature/top-p 引入隨機
↓
3. 硬件/併發：浮點非確定性
↓
4. 系統提示詞、上下文、時間：外層擾動
↓
最終輸出：一次"抽樣"

這跟傳統 API 有一個根本區別——傳統 API 的核心屬性是冪等性（idempotency）： 你把同樣的請求發 100 次，結果一樣。而 LLM API天然不是冪等的。 這意味著所有依賴冪等的中間件（緩存、重試、去重）都得重新想。

權衡層：為什麼這樣設計？

你會問：既然確定性這麼好，為什麼不做成 greedy（永遠選最大概率）呢？ 答案是——永遠選最大概率，效果反而更差。

😐 Greedy（溫度 0）

每步都選最大概率的 token。
結果：安全、無聊、重複。
寫代碼合適（要正確），
寫故事就變白開水。

🎲 Sampling（溫度 > 0）

允許偶爾選次優 token。
結果：更多樣、更有創意。
寫作、頭腦風暴合適，
但也更容易跑偏。

所以"概率性"其實是一個可調節的旋鈕：

  • 做代碼補全、翻譯、事實問答 → 調低溫度，靠近確定性
  • 做創意寫作、頭腦風暴、命名生成 → 調高溫度，歡迎不確定
  • 做 Agent 決策鏈 → 常常溫度 0，減少累積誤差
換個視角：傳統系統追求"每次結果一樣"， 因為它們是確定性問題的確定性求解；
AI 系統追求"平均結果好"， 因為它們面對的是本身沒有唯一答案的問題（寫作、總結、推理）。

"這封郵件寫得好不好？" ——這問題根本沒有唯一答案。 所以 AI 的輸出方式，是與問題的性質匹配的。

✋ 動手試試

親自看"同題不同答"

在 OpenAI Playground 或任何提供 API 的 AI 平臺上：

  1. 寫一個 prompt："用一句話描述海邊的日落。"
  2. 把 temperature 設為 0，跑 3 次 → 3 次幾乎相同。
  3. 把 temperature 設為 1.2，再跑 3 次 → 明顯不同。
  4. 把 temperature 拉到 2.0 試試 → 可能開始"胡言亂語"。

這個實驗會給你一個手感：溫度不是"AI 有多聰明"的旋鈕， 而是"AI 允許自己走多遠"的旋鈕。

👑 大帝視角：這如何塑造現實？

可靠性的定義正在被重寫

我們過去評估軟件的方式，是斷言等價： "輸入 X → 輸出必須是 Y"。CI 裡跑 assert，紅了就是壞了。

但當你把 LLM 放進生產系統，這套方法完全失效—— 因為答案本來就是一個"分佈"，你要評估的是"分佈好不好"，不是"某次抽樣等不等於某個字符串"。

這催生了一個新的工程學科：Evals（評估）。

  • 不再問"輸出等於什麼"，而問"輸出的分佈，在我關心的維度上分數如何"。
  • 不再靠 CI 一次通過，而靠大樣本統計決定要不要發佈。
  • 不再期待"零 bug"，而接受"錯誤率 5%，且可監控可回滾"。

在第 6 層認知裡，你要學會一件反直覺的事： 接受一個 90% 靠譜的系統，比追求一個 100% 但做不出來的系統更工程。

✨ 回到問題

為什麼 AI 系統的輸出帶有概率性，而不是傳統系統那樣的確定性？

因為 AI 處理的問題本身就沒有唯一答案，它的機制是"從分佈裡採樣"，而不是"按規則求解"。 概率性不是它的缺陷，而是它能處理開放問題（寫作、推理、生成）的代價與前提。

換一種衡量的標尺：
傳統系統的可靠 = 每次都對。
AI 系統的可靠 = 分佈上足夠好，且失敗可監控可回滾。

當你換掉這把尺子，你才真正進入了 AI 時代的思維方式。
