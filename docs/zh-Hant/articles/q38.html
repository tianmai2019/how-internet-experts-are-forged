為什麼商業目標常常決定技術路線，而不只是反過來？

技術不是自主生長的樹，是商業的孩子

🤔 小白視角：這個問題為什麼重要？

同樣是社交產品——

  • Facebook 花了 10 年重構成"移動優先"，因為廣告錢在手機上；
  • 微信一直"剋制"，因為它的商業是通信 + 生態，不是流量；
  • TikTok 瘋狂投資推薦算法，因為它的商業是"廣告注意力"；
  • Slack 瘋狂投穩定性，因為它賣的是 B 端訂閱，宕機就退款。

你有沒有想過：為什麼它們的技術選擇差別這麼大？

因為技術不是"最優解"，技術是"商業模式的孩子"。

你收錢的方式決定了你必須服務的指標；
你必須服務的指標決定了你必須優化的技術；
你必須優化的技術決定了你的架構、語言、算法、組織。

🧩 拆解：把大問題拆成小問題

  1. 不同商業模式對應什麼樣的技術側重？
  2. Facebook 從桌面到移動，技術上到底發生了什麼？
  3. 為什麼"廣告驅動"和"訂閱驅動"技術路線截然不同？
  4. "技術選型"看起來是工程師的事，其實是 CFO 的事？

🎯 一層一層看

用戶層：只看結果

用戶體驗到："這個 App 廣告好多。""這個 App 免費但推薦很準。""這個 App 收月費但特別穩定。" 這些不是巧合，是商業模式對用戶體驗的直接投射。

實現層：開始理解構造

商業目標 → 關鍵指標 → 技術投入的映射：

// 廣告驅動的產品（Facebook / TikTok / 微博） Key Metric: DAU × 停留時長 × 廣告展示 × CPM Tech Focus: - 推薦算法（把注意力最大化） - 視頻編解碼（降低帶寬成本） - 廣告投放系統（毫秒級競價） - AB 測試基礎設施（每天上百個實驗） // 訂閱驅動的產品（Netflix / Slack / Notion） Key Metric: 付費用戶數 × ARPU × 留存率 Tech Focus: - 穩定性（宕機 = 退款） - 內容質量（Netflix 甚至自建 CDN） - 企業級安全（SOC2、單點登錄、審計日誌） - 客戶成功系統（不是"增長黑客"） // 交易驅動的產品（淘寶 / 拼多多 / 美團） Key Metric: GMV × 佣金率 Tech Focus: - 搜索/推薦（把商品匹配到人） - 庫存/物流/支付（一致性極高的分佈式) - 反欺詐風控（每一分錢都要保護） - 大促容量（雙 11 需要 100 倍平時容量）

你看到了嗎？同樣叫"後端工程師"，在這三種公司裡，工作內容完全不同。 他們的技術能力，最終由公司怎麼賺錢塑造。

系統層：看到完整鏈路

Facebook 2012 年"移動重構"，是一個教科書級案例：

2011: 廣告 70% 來自桌面 Web ↓ 但用戶 60%+ 時間在手機上 ↓ 商業壓力：如果不移動化，廣告會斷崖 ↓ Facebook 花 1 年多，砍掉 HTML5 混合方案 ↓ 重寫 iOS/Android 原生 App ↓ 改造廣告投放系統適應移動信息流 ↓ 2014: 移動廣告收入超越桌面 ↓ Zuckerberg 後來說："這是公司歷史上最重要的技術決定"

這個決定不是"技術上更先進"驅動的——是商業模式的存亡驅動的。

權衡層：為什麼這樣設計？

商業模式和技術路線的對應關係，可以理解為一個"權衡矩陣"：

免費廣告模式

技術必須服務"注意力最大化"——推薦、算法、AB 測試。用戶體驗被"停留時長"綁架。

付費訂閱模式

技術必須服務"用戶長期價值"——穩定、隱私、體驗。用戶體驗就是產品本身。

交易佣金模式

技術必須服務"每一筆交易都成功"——一致性、風控、履約。技術必須"錙銖必較"。

開源 / 開發者模式

技術必須服務"生態繁榮"——文檔、API 穩定、社區。技術本身就是產品。

"技術選型"表面是工程決策，本質是商業決策。 這就是為什麼真正的技術領導，都在 CEO 桌子邊坐著，而不是縮在服務器機房裡。

✋ 動手試試

🔍 觀察實驗：一個 App 是靠什麼賺錢？

隨便挑一個你常用的 App，問自己：

  1. 它靠什麼賺錢？廣告？訂閱？交易？還是數據？
  2. 基於這個盈利模式，它一定會重視哪些技術指標？
  3. 反過來，它一定會"忽略"什麼？（比如：廣告驅動的產品，很少投入到"幫你減少使用時長"上）
  4. 把這個邏輯用到你正在做的項目上——你在為哪個商業目標寫代碼？

技術路線是商業模式的孩子

技術圈有一種迷思："我只做技術，不問商業。" 但大帝視角揭示的真相是：你選擇用哪種技術、優化哪個指標、加班到幾點，全都是商業模式在替你做決定。

這解釋了很多"技術圈的宿命"：

  • 為什麼算法工程師工資最高？因為他們直接決定"推薦→點擊→廣告"這條錢路；
  • 為什麼運維在很多互聯網公司地位低？因為他們的價值是"減少崩潰"，而崩潰不常發生；
  • 為什麼 Cloudflare 這種基礎設施公司願意花天價養安全團隊？因為他們賣的就是"永不宕機"；
  • 為什麼 GitHub 從"個人工具"變"企業 SaaS"後，產品變化那麼大？——收錢的對象變了。

再進一步：整個互聯網大廠的技術方向，本質上是被資本市場和收入結構定義的。 廣告收入的公司，永遠會做推薦；訂閱收入的公司，永遠會做穩定；交易收入的公司，永遠會做風控。 你想讓技術"走另一條路"，先得改變它的錢來自哪裡。

所以"技術自主"是個美好但脆弱的口號。真正的技術自主，是知道自己在為誰的錢寫代碼，並有能力選擇。

✨ 回到問題

所以，為什麼商業目標常常決定技術路線？

答案是：因為技術需要資源、資源需要資金、資金需要商業模式支撐。 這條鏈條不是從"技術能做什麼"開始的，是從"用戶願意為什麼付錢"開始的。 技術不是"從上往下"生長的樹，是"從錢往上"生長的植物——你的商業模式，就是它的土壤。

大帝視角的覺醒：

下次聽到"這是技術決策"，多想一步——
誰的錢在推動這個決策？他們要什麼？
看到這一層，你才真正開始理解一家互聯網公司。
